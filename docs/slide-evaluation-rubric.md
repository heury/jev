# 강의 슬라이드 평가 기준

`slides.md`(Slidev)로 만든 강의 자료가 잘 작성되었는지 판단하는 기준이다.
jev 강의를 평가하며 만들었지만 다른 Slidev 강의에도 그대로 쓸 수 있다.

- 최초 작성: 2026-10-13
- 대상 독자: 강의 작성자, 그리고 슬라이드를 고치거나 다시 평가하는 사람·에이전트

---

## 1. 채점 방법

- 각 항목을 **0점(미흡) · 1점(부분 충족) · 2점(충족)**으로 매긴다.
- 영역 점수 = (획득 점수 ÷ 영역 만점) × 가중치
- 측정할 수 없는 항목(예: 수강생이 없는 상태의 H-2)은 빼고, 측정한 영역의 가중치 합으로 나눠 100점으로 환산한다.
- 직접 확인할 수 있는 항목(빌드, 링크, 노트북 실행, 렌더링)은 **반드시 실제로 실행해서** 채점한다. 눈으로만 판단하지 않는다.
- 자기 채점은 후하게 나오기 쉽다. 점수와 함께 **근거(장 번호, 측정값)**를 남긴다.

### 영역과 가중치 (합계 100)

| 영역 | 가중치 | 보는 것 |
|---|---|---|
| A. 학습 목표와 정렬 | 10 | 목표가 측정 가능하고 내용·실습·질문과 연결되는가 |
| B. 기술적 정확성 | 17 | 식·사실·수치가 맞고 출처와 조건이 있는가 |
| C. 구조와 시간 배분 | 8 | 아젠다와 실제 진행이 맞고 실현 가능한가 |
| D. 슬라이드 설계 | 7 | 밀도·가독성·렌더링 오류 |
| E. 실습 연계와 재현성 | 13 | 슬라이드와 노트북이 일치하고 재현되는가 |
| F. 상호작용과 형성평가 | 10 | 예측·토론·확인 활동이 있는가 |

| H. 모델 설명 이해도 | 15 | 자료의 설명 품질(H-1 7.5) + 학습자 이해도(H-2 7.5) |
| I. 시각 표현력 | 15 | 그림·표·차트와 강조로 쉽게 이해되는가 |

### I. 시각 표현력 (15) — Slidev 렌더링 기준

**원칙:** 글로 설명할 내용을 다이어그램·이미지·표·차트로 바꿀수록, 그리고 볼드나 색으로 핵심을 절제해서 강조할수록 점수가 높다.
**측정 범위:** 렌더링된 export 페이지의 콘텐츠 장 (표지·구분·출처 장 제외).

|---|---|---|---|---|---|
| I1 | 시각 요소 비율 | 표·다이어그램·이미지·카드 그리드·2단 비교가 있는 장의 비율 | ≥80% | 50~80% | <50% |
| I2 | 다이어그램 대체율 | 흐름·구조·관계·절차 설명 장 중 다이어그램으로 표현한 비율 | ≥70% | 30~70% | <30% |
| I3 | 수치의 시각화 | 분포·곡선·전후 비교를 차트로 보여준 비율 | ≥50% | 20~50% | <20% |
| I4 | 글만 있는 장 | 시각 요소와 코드 없이 문장만 있는 장 (퀴즈 제외) | 0~1장 | 2~4장 | ≥5장 |

## 3. 수강생 관점 검토 (정성 평가)

점수와 별개로, 대상 수강생(jev 강의라면 "딥러닝은 알지만 결정 모델은 처음인 사람")이 되어 슬라이드를 **처음부터 순서대로** 읽고 아래를 찾는다.
여기서 나온 지적은 대부분 B5, H7, H8, F 항목의 점수에도 반영된다.

| 유형 | 찾는 것 | jev 강의에서 실제로 나온 예 |
|---|---|---|
| 정의 순서 | 용어가 정의되기 전에 쓰였는가 | `noul`이 9장에 나오는데 정의는 11장. 12장 차트에 아직 안 배운 ECE·보정이 나옴 |
| 같은 단어, 다른 의미 | 한 장 안에서 같은 단어를 반대 의미로 썼는가 | "헤드가 함께 디코딩" 바로 아래 "decoding은 없다" |
| 기존 지식과 충돌 | 수강생이 이미 아는 같은 이름의 개념과 헷갈리는가 | 보정 온도 vs LLM 샘플링 온도 |
| 답할 수 없는 질문 | 마무리 질문의 답이 본문에 있는가 (노트에만 있으면 실패) | `jev-latest`의 답이 발표자 노트에만 있었음 |
| 근거 없는 숫자 | 기준값·선택값의 이유가 보이는가 | 임계값 0.85의 선택 규칙, 허용오차 0.02의 근거 |
| 라벨 없는 수치 | 표의 수치가 무엇의 전후·어떤 지표인지 적혀 있는가 | "36% → 73%"가 무엇인지 없었음 |
| 실행 위치 | 무엇을 어디서(PC/서버) 실행하는지 분명한가 | 노트북 03을 PC에서 돌리는지 서버에서 돌리는지 |
| 직관과 반대 | 직관과 반대되는 설정에 설명이 있는가 | 새 헤드 학습률(1e-4)이 LoRA(2e-4)보다 낮음 |

검토 결과는 "가장 헷갈린 것 5개 → 장별 메모 → 좋았던 점 → 제안" 순서로 정리한다.

## 4. 자동 검사 절차

수정할 때마다 아래를 실행한다. **PDF export는 수정마다 하지 않는다.** 요청이 있을 때만 `npx slidev export`를 실행한다.

1. **빌드:** `npm run build` (오류 0건)
2. **렌더링 검사:** `npx slidev slides.md --port 3031`(또는 실행 중인 dev 서버)의 `/export` 페이지를 Playwright로 열어, 장마다 다음을 확인한다.
   - 요소(`h1, p, table, pre, li, .callout, .source, .card, svg, .legend, .caption, .stat-card`)가 `.slidev-layout` 경계를 넘는가
   - `pre`에 가로 스크롤이 생기는가
3. **스크린샷 확인:** 바뀐 장은 스크린샷을 찍어 **직접 본다.** 자동 검사가 놓치는 문제가 있다.
   - SVG나 mermaid가 컨테이너 안에서 잘리는 경우 (경계 검사에 안 걸림)
   - 글자 크기 이상
4. **노트북:** 01·03은 `jupyter nbconvert --to notebook --execute`로 새 커널에서 완주한다.
5. **링크:** 모든 URL의 HTTP 상태를 확인한다.

Playwright용 Chromium이 없으면 `executablePath`에 시스템 Chrome(`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`)을 지정한다.

### Slidev에서 실제로 겪은 함정

- **UnoCSS attributify:** SVG의 `font-size="12"` 속성이 유틸리티 클래스로 해석되어 `3rem`(48px)이 된다. SVG 글자 크기는 반드시 `style="font-size:12px"`로 쓴다. `stroke`, `stroke-width`도 같은 규칙에 걸리지만 같은 값으로 해석되어 무해하다.
- **mermaid 노드 라벨:** 긴 한국어 라벨은 단어 중간에서 끊긴다. 라벨을 짧게 쓰고 `<br/>`로 줄을 나눈다. 노드가 6개 이상인 `LR` 흐름도는 `scale` 0.8~0.86에서 너비를 확인한다.
- **mermaid 감지:** 렌더링된 mermaid SVG는 일반 선택자로 잡히지 않을 수 있다. 다이어그램 수는 소스에서 센다.
- **export와 클릭:** PDF·export 페이지는 `v-click`이 모두 펼쳐진 상태로 렌더링된다. 실제 발표에서는 클릭해야 보인다.
